# 옥천 AI Class · 수강생별 로컬 앱 개발 시작 프롬프트

작성일: 2026년 10월 14일  
기획 기준: [1회차 수강생 앱 기획과 개발 준비](lesson-one-student-projects.md)

이 문서는 실제 앱 구현물이 아니라 **Codex 또는 Claude Code에 붙여 넣을 개발 지시문**입니다. 원 기획의 배포 설계에 앞서, 각자의 컴퓨터에서 실행하는 첫 버전을 만듭니다. DB는 필요한 앱에만 SQLite를 사용하고 영상은 프로젝트 안의 로컬 폴더에 저장합니다.

## 사용 방법

1. 학생마다 **새 프로젝트 폴더**를 만듭니다. 수업 홈페이지 저장소 안에서 실행하면 기존 홈페이지를 수정할 수 있으므로 별도 폴더를 사용합니다.
2. 터미널에서 그 폴더를 열고 `codex` 또는 `claude`를 실행합니다. 앱에서 Codex를 사용하는 경우 그 폴더를 프로젝트로 엽니다. 실행 환경이 요구하는 Node.js와 패키지 관리자가 설치되어 있어야 합니다.
3. 아래에서 **본인 이름의 코드 블록 전체를 한 번에** 붙여 넣습니다. 각 블록은 공통 개발 조건을 포함하므로 다른 블록을 함께 복사하지 않아도 됩니다.
4. 도구가 알려주는 설치·실행 결과를 확인하고 `http://127.0.0.1:3000` 또는 실제 안내된 포트를 브라우저에서 엽니다. 실행에 실패하면 마지막 절의 후속 프롬프트를 사용합니다.
5. AI API 키는 채팅에 붙이지 말고 로컬 `.env.local`에 넣습니다. AI 앱은 키 없이 데모로 먼저 확인하고, 실제 생성이 필요할 때 공급자의 API URL·모델·키를 설정합니다.

### 첫 버전에서 달라지는 점

| 수강생 / 앱 | SQLite | 로컬 파일 폴더 | AI / 로그인 범위 |
| --- | --- | --- | --- |
| 김기택 / 안녕 옥천 | 행사 CRUD | 불필요 | AI 없음, 로컬 관리자 비밀번호 |
| 김승애 / GAEMEJAE | 작품·파일 정보 | 영상 업로드 및 임시 처리 | AI 없음, 로컬 작가 비밀번호 |
| 심현정 / 칼퇴도우미 | 일정 | 불필요 | AI 없음, 개인용 |
| 이봄길민들레 / 사료 측정앱 | 불필요 | 불필요 | AI 없음, 열량→무게 환산 |
| 전필우 / 파워포인트 끝판왕 | 구성안·슬라이드 | 불필요 | 데모/실제 AI, 개인용 |
| 홍용훈 / 헬퍼라이터 | 작품·인물·초안 버전 | 불필요 | 데모/실제 AI, 개인용 |

여기서 파일 서버는 별도 클라우드 상품이나 별도 프로세스가 아니라 **Next.js 서버가 업로드 폴더의 파일을 API로 제공하는 기능**입니다. `.local-data/tmp`는 임시 작업 폴더이고 `.local-data/uploads`는 실습 중 보관할 원본 폴더입니다. 업로드 원본을 운영체제 임시 폴더에만 보관하면 정리 과정에서 사라질 수 있으므로 둘을 나눕니다. 로컬 DB와 업로드 폴더는 자동 백업되지 않으며 이 구성을 그대로 Vercel의 영구 저장용으로 쓰지 않습니다.

## 1. 김기택 · 안녕 옥천

아래 전체를 복사해서 입력합니다.

```text
내가 만들 앱은 "안녕 옥천"이야. 아래 조건에 맞춰 첫 버전을 실제로 구현해줘.

공통 개발 조건:
- 설명이나 계획만 제시하지 말고 실제 파일을 만들고, 의존성을 설치하고, 로컬에서 실행 가능한 앱을 완성해줘. 중간에 오류가 발생하면 원인을 찾아 수정해줘.
- 현재 폴더는 아무 파일도 없는 빈 폴더야. Next.js App Router + TypeScript 프로젝트를 처음부터 생성하고 package.json, 실행 스크립트, 기본 설정과 필요한 의존성을 구성해줘. Next.js가 설치되면 node_modules/next/dist/docs/의 관련 가이드를 읽고 설치된 버전에 맞춰 구현해줘.
- 한국어 UI, 모바일 대응, 읽기 쉬운 글자와 충분히 큰 버튼을 사용해줘. 로딩, 빈 목록, 입력 오류, 서버 오류, 저장 성공 상태를 구현해줘. 모든 입력에는 label을 붙이고 키보드로 조작 가능하게 만들어줘.
- 이번 작업은 내 컴퓨터의 로컬 실습용이야. dev/start 서버는 127.0.0.1에 바인딩해줘. 배포, 외부 DB, 클라우드 파일 저장소, 유료 서비스 가입은 진행하지 마.
- DB가 필요한 기능은 SQLite를 사용하고 기본 파일은 .local-data/app.sqlite로 만들어줘. SQL과 파일 작업은 Node.js 서버에서만 실행해줘. 현재 Node 버전과 호환되는 SQLite 드라이버 하나를 선택하고 README에 선택 이유를 적어줘. 파라미터 바인딩, 필요한 인덱스와 외래키, 연결 재사용을 적용해줘.
- DB 초기화/마이그레이션과 샘플 데이터 입력 명령을 제공해줘. seed를 두 번 실행해도 데이터가 중복되지 않게 해줘. 개발 서버 재시작 시 DB를 지우거나 샘플로 덮어쓰지 마. DB가 필요 없는 앱에는 불필요한 DB를 추가하지 마.
- 파일 저장이 필요한 경우 프로젝트 안의 .local-data/uploads와 .local-data/tmp를 만들어 로컬 파일 서버 API로 제공해줘. uploads는 삭제할 때까지 유지하고 tmp는 실패한 업로드 등 임시 처리에 사용해줘. public/에 사용자 업로드를 저장하지 마. DB에는 원본 바이너리 대신 파일 ID, 상대 저장 키, 원본명, MIME, 크기를 저장해줘.
- .local-data/, .env.local, 로그는 Git에서 제외해줘. 예제 설정은 .env.example에 비밀값 없이 적어줘. 서버 비밀키를 NEXT_PUBLIC_ 변수에 넣지 마.
- 파일/DB/AI 접근 코드는 각각 서버 모듈로 분리해서 나중에 교체하기 쉽게 해줘. 첫 버전에 필요한 구조만 만들고 과한 추상화는 하지 마.
- README에 설치, 환경변수, 초기화, seed, 실행, 데이터/파일 위치, 서버 중지 후 백업/복구, 알려진 제한을 초보자도 따라 할 수 있게 적어줘. 데이터 초기화는 별도 명령으로만 제공하고 삭제 전에 명시적으로 확인하도록 해줘.
- 구현 후 타입 검사, 린트, 프로덕션 빌드를 확인하고 관련 오류를 수정해줘. 핵심 동작을 확인하고 실제 수행한 검사와 수행하지 못한 검사를 구분해서 알려줘. 앱을 열 주소, 실행 명령, 변경 파일을 마지막에 정리해줘.

앱 목적과 범위:
옥천 주민이 문화행사를 찾아보는 앱을 만들어줘. 첫 버전은 행사 조회와 로컬 관리자 CRUD까지야. 자동 크롤링, AI 검색, 사용자 게시판, 포스터 업로드는 제외해줘.

화면과 흐름:
1. / 에 행사 카드 목록, 검색창, 카테고리 선택(전체/공연/교육/원데이 클래스), 날짜 범위, 이번 주말 버튼을 배치해줘.
2. 카드에 행사명, 종류, 한국 시간의 시작·종료 일시, 장소, 진행 상태를 표시해줘. 클릭하면 /events/[id] 상세 화면으로 이동해줘.
3. 상세 화면에 소개, 주최 기관, 신청 방법, 원문 링크, 최종 확인일, 상태를 표시해줘. 출처 링크는 http/https만 허용해줘.
4. /admin 에 행사 등록·수정·삭제 화면을 만들어줘. 삭제 전 확인하고 저장 후 목록과 상세에 변경이 반영되게 해줘.
5. 로컬 관리자 비밀번호를 LOCAL_ADMIN_PASSWORD 환경변수로 설정하고 서버에서 확인해줘. 성공하면 만료 시간이 있는 HttpOnly/SameSite 쿠키 세션을 발급하고 관리자 화면뿐 아니라 쓰기 API 모두에서 검증해줘. 로그아웃도 제공해줘. 비밀번호가 없으면 관리자 기능을 잠그고 설정 방법을 안내해줘. 상태 변경 요청은 동일 출처를 확인해줘.

SQLite 구조:
events: id, title, category, starts_at, ends_at, venue, description, organizer, application_info, source_url, checked_at, status, created_at, updated_at.
status는 scheduled/cancelled, category는 정의한 세 종류만 허용해줘. title, 시작·종료, venue는 필수이며 종료가 시작보다 빠르면 저장하지 마.
한국 시간으로 입력받고 UTC ISO 문자열로 저장해줘. 날짜 필터는 Asia/Seoul 기준으로 계산해줘.

날짜 동작:
이번 주말은 월~금에는 다가오는 토·일, 토·일에는 현재 주말이야. 토요일 00:00 이상, 다음 월요일 00:00 미만의 구간과 겹치는 행사를 보여줘. 행사 시작만 검사하지 말고 며칠간 계속되는 행사도 포함해줘. 취소 행사는 배지를 표시하고 기본 목록에서는 숨기되 '취소 행사 포함' 선택으로 볼 수 있게 해줘.

샘플과 확인:
실제 행사로 오해하지 않도록 '수업용 가상 행사' 배지를 붙인 8개를 만들어줘. seed 실행일을 기준으로 평일, 이번 주말, 다음 주말, 여러 날 행사, 취소 행사를 섞어줘. 임의의 실제 출처 URL을 만들지 말고 없는 출처는 미등록으로 표시해줘.
등록→검색→상세→수정→삭제가 동작하고 재시작 후 데이터가 유지되는지 확인해줘. 주말 경계와 날짜 겹침 로직에는 작은 단위 테스트를 작성해줘. 인증 없는 쓰기 API 요청이 거부되는지도 확인해줘.
```

첫 버전은 작품당 영상 1개만 허용해줘. 파일 교체는 새 영상 업로드와 DB 반영이 성공한 뒤 이전 파일을 정리해줘.

로컬 파일 서버:
.local-data/tmp에 업로드한 뒤 검증과 저장이 성공하면 .local-data/uploads로 옮겨줘. UUID 저장 키를 생성하고 사용자가 준 파일명으로 경로를 만들지 마. DB와 파일은 하나의 트랜잭션이 아니므로 실패 단계별 정리와 복구 방식을 구현해줘. 삭제 실패는 기록하고 이후 정리할 수 있게 해줘.

영상은 최대 50MB의 MP4만 허용해줘. 브라우저 검사 외에 서버에서도 크기, 확장자, MIME과 MP4 컨테이너 헤더를 검사해줘. 허용 크기를 넘으면 읽기를 중단하고 임시 파일을 정리해줘. 사용 중인 Next.js 업로드 경로가 이 제한을 지원하도록 확인해줘.
영상 탐색이 가능하도록 GET/HEAD와 단일 HTTP Range 요청을 지원해줘. 206, Content-Range, Accept-Ranges, Content-Length를 정확히 반환하고 잘못된 범위는 416으로 처리해줘. 전체 파일을 매번 메모리에 읽지 말고 스트리밍해줘.

샘플과 확인:
내가 영상을 준비하지 않아도 빈 상태에서 시작할 수 있게 해줘. 가짜 외부 영상 주소를 샘플로 넣지 마. README에 사용 권한이 있는 짧은 MP4 준비 방법과 브라우저별 코덱 호환성 제한을 적어줘.

고양이의 하루 사료 무게를 계산하는 로컬 도구를 만들어줘. 첫 버전은 '전문가에게 안내받은 하루 필요 열량을 사료 g으로 환산'하는 기능이야. 나이·체중만으로 감량 처방이나 권장 열량을 만들어내지 마. DB, 파일 업로드, 로그인, AI, 제품 추천은 필요 없어.

화면과 입력:
1. 고양이 이름(선택), 나이, 현재 체중 kg, 중성화 여부를 기록용 입력으로 받아줘. 이 정보가 아래 환산식에서 필요 열량을 결정하지 않는다고 명확하게 표시해줘.
2. '전문가에게 안내받은 하루 필요 열량'을 kcal/day 단위로 입력받아줘. 값을 모르면 계산하지 않고 전문가 확인 후 입력하도록 안내해줘.
3. 사료 포장에 적힌 에너지 수치와 단위를 받아줘. kcal/kg, kcal/100g, kcal/g를 명시적으로 선택하게 해줘. kJ나 '한 컵' 등 지원하지 않는 단위는 추정 변환하지 마.
4. 급여 횟수는 1~6 정수로 입력받아줘. 간식·다른 음식의 하루 열량은 선택 입력으로 받아줘. 비워두면 0으로 해석하고, 음수이거나 총 필요 열량 이상이면 계산을 중단하고 확인을 요청해줘.

계산 규칙:
kcal/kg 입력은 1000으로 나누고 kcal/100g은 100으로 나눠 kcal/g로 정규화해줘.
사료로 채울 열량 = 안내받은 하루 열량 - 간식 및 다른 음식의 열량.
하루 사료 g = 사료로 채울 열량 / 사료의 kcal/g.
1회 사료 g = 하루 사료 g / 급여 횟수.
계산 중간값은 반올림하지 말고 화면에서만 소수점 첫째 자리로 표시해줘. 이 규칙은 열량→무게 환산 규칙이며 건강 상태별 급여 처방이 아니야. 규칙 버전 energy-to-grams-v1을 결과에 표시해줘.
모든 숫자에 빈칸, NaN, Infinity, 0, 음수 검증을 적용해줘. 나이·체중·급여 횟수의 유효성을 확인하되 임의의 수의학적 정상 범위를 만들지 마.

결과와 사용자 경험:
하루 총 g, 1회 g, 적용한 하루 열량, 간식 열량, 환산한 kcal/g, 계산식과 대입값을 보여줘. 전문가 안내값을 확인했는지 체크한 후 계산할 수 있게 해줘. 입력 변경 시 이전 결과를 '이전 입력의 결과'로 표시하거나 지워줘.
'이 결과는 입력한 열량을 무게로 환산한 값입니다. 성장기·임신·수유·질환·체중 감량 계획의 필요 열량은 수의 전문가에게 확인하세요.'라고 안내해줘.
예제 입력 버튼은 '수업용 수학 예제이며 실제 급여 권장값이 아님'을 표시해줘. 초기값을 실제 권장량처럼 자동 채우지 마. 새로고침 시 입력이 사라질 수 있고 기록 저장은 이번 버전에 없음을 안내해줘.

확인:
단위 테스트를 작성해줘. 수학 예제로 하루 200kcal, 간식 20kcal, 사료 4000kcal/kg, 2회일 때 하루 45g, 1회 22.5g이어야 해. 400kcal/100g, 4kcal/g를 입력해도 같은 결과여야 해.
빈 열량, 열량 0/음수, 잘못된 단위, 간식이 총 열량 이상, 소수 급여 횟수는 거부해줘. 화면에 검증되지 않은 필요 열량 공식이나 감량 처방이 들어가지 않았는지도 확인해줘.
```

demo 모드는 입력 주제와 핵심 내용을 사용해 정확한 개수의 예제 구조를 만들고 '데모 결과: 외부 AI 미사용' 배지를 표시해줘. live 호출 버튼 근처에 입력 내용과 참고 텍스트가 외부 AI로 전달됨을 표시해줘. 키나 입력 전문을 로그에 남기지 마.

- 파일 저장이 필요한 경우 프로젝트 안의 .local-data/uploads와 .local-data/tmp를 만들어 로컬 파일 서버 API로 제공해줘. uploads는 삭제할 때까지 유지하고 tmp는 실패한 업로드 등 임시 처리에 사용해줘. public/에 사용자 업로드를 저장하지 마. DB에는 원본 바이너리 대신 파일 ID, 상대 저장 키, 원본명, MIME, 크기를 저장해줘.
- .local-data/, .env.local, 로그는 Git에서 제외해줘. 예제 설정은 .env.example에 비밀값 없이 적어줘. 서버 비밀키를 NEXT_PUBLIC_ 변수에 넣지 마.
- 파일/DB/AI 접근 코드는 각각 서버 모듈로 분리해서 나중에 교체하기 쉽게 해줘. 첫 버전에 필요한 구조만 만들고 과한 추상화는 하지 마.
- README에 설치, 환경변수, 초기화, seed, 실행, 데이터/파일 위치, 서버 중지 후 백업/복구, 알려진 제한을 초보자도 따라 할 수 있게 적어줘. 데이터 초기화는 별도 명령으로만 제공하고 삭제 전에 명시적으로 확인하도록 해줘.
- 구현 후 타입 검사, 린트, 프로덕션 빌드를 확인하고 관련 오류를 수정해줘. 핵심 동작을 확인하고 실제 수행한 검사와 수행하지 못한 검사를 구분해서 알려줘. 앱을 열 주소, 실행 명령, 변경 파일을 마지막에 정리해줘.

앱 목적과 범위:
웹소설 작가가 작품·인물·장면을 입력하고 대화문 초안을 만드는 로컬 앱을 만들어줘. 첫 버전은 작품과 인물 관리, 장면별 대화문 생성, 편집, 버전 보존, 텍스트 다운로드야. 긴 원고 업로드, 회차 자동 분석, 임베딩/벡터 DB, 자율 집필, 외부 로그인은 제외해줘.

화면과 흐름:
1. / 에 작품 목록과 새 작품 버튼을 만들어줘. 작품에는 제목, 장르, 세계관 핵심 규칙을 입력해줘.
2. /projects/[id] 에 인물 등록·수정·삭제 영역을 만들어줘. 인물에는 이름, 성격, 말투, 다른 인물과의 관계를 입력해줘.
3. 장면 생성 폼에서 해당 작품의 인물 2~4명, 장소·상황, 장면 목표, 분위기, 길이(짧게/보통/길게), 피하고 싶은 표현을 선택·입력해줘.
4. 결과에 읽기 화면과 편집 textarea를 제공하고 'AI 초안' 또는 '데모 초안'을 표시해줘. 편집 후 새 버전 저장, 다른 버전 생성, 두 버전 나란히 보기, txt/Markdown 다운로드를 제공해줘.
5. 버전별 생성 시간과 생성 조건을 확인할 수 있게 해줘. 이전 버전을 읽기 전용으로 열고 필요하면 복사해 새 버전을 만들어줘. 미저장 편집이 있을 때 작품 전환과 재생성 전에 확인해줘.

SQLite 구조:
projects: id, title, genre, world_rules, created_at, updated_at.
characters: id, project_id(FK), name, traits, speech_style, relationships, created_at, updated_at.
scenes: id, project_id(FK), title, situation, goal, mood, created_at, updated_at.
generations: id, scene_id(FK), version_number, selected_character_ids_json, input_snapshot_json, output_text, source(demo/ai/manual), created_at.
버전은 insert로 쌓고 이전 본문을 update로 덮어쓰지 마. 장면별 version_number 중복을 막고 새 버전 번호와 저장을 트랜잭션으로 처리해줘. 인물 설정이 바뀌어도 당시 입력을 input_snapshot_json에서 확인할 수 있게 해줘.
API는 장면/인물이 요청 작품에 속하는지 확인하고 다른 작품의 인물 ID가 섞인 요청은 거부해줘. 작품 삭제는 인물·장면·버전 전체 삭제를 명확히 안내한 뒤 확인해줘. 한 컴퓨터의 한 사용자용 앱이며 로그인과 다중 사용자 보안을 제공한다고 표현하지 마.

AI 구현:
AI_MODE=demo|live, AI_BASE_URL, AI_API_KEY, AI_MODEL을 서버에서만 사용해줘. 키가 없으면 기본 demo 모드로 실행하고, 명시적 live 모드에서 설정이 부족하면 오류로 처리해줘. 외부 호출 코드는 OpenAI 호환 API용 서버 모듈로 분리해줘.
시스템 역할은 '작가가 검토할 웹소설 대화문 초안을 제안하는 보조 작가'야. 선택 작품의 세계관 규칙, 선택한 인물 정보, 관계, 현재 장면과 요청 길이만 전달해줘. 다른 작품이나 전체 DB를 보내지 마. 저장한 모든 내용을 AI가 자동으로 기억한다고 표현하지 마.
사용자 자료는 참고 내용으로 전달하고 그 안의 지시가 시스템 지시를 바꾸지 않게 해줘. 인물 말투를 구별하고 대사와 필요한 짧은 지문을 함께 생성하도록 요청해줘. 입력에 없는 새 설정은 확정 사실처럼 만들지 말고 '검토할 설정 제안'으로 따로 표시하도록 해줘.
작품명 200자, 세계관 10000자, 인물 각 정보 2000자, 장면 10000자 등 길이 제한을 서버에도 적용하고 출력 최대 길이와 60초 시간 제한을 설정해줘. 실패하면 장면 입력과 기존 편집본을 유지하고 수동 재시도를 제공해줘.
demo는 선택 인물 이름과 상황을 반영한 짧은 예제 대화를 만들고 '데모: 외부 AI 미사용'을 명확하게 표시해줘. live 생성 전에 전송되는 항목을 화면에 안내해줘. 키, 원고 전문과 인물 설정을 로그에 남기지 마. 파일 서버는 텍스트 다운로드에 필요 없어.

샘플과 확인:
저작권 문제가 없는 직접 만든 샘플 작품 2개와 작품마다 인물 2명, 장면 1개를 seed로 넣어줘. 서로 다른 장르와 말투로 작품 구분을 확인할 수 있게 해줘.
작품 선택→인물 수정→생성→편집→새 버전 저장→비교→다운로드, 재시작 후 버전 보존을 확인해줘. 다른 작품 인물의 선택/API 주입이 거부되는지, 생성 실패 시 기존 원고가 유지되는지 검증해줘. 실제 키가 없으면 live 미검증임을 알려줘.
```

앱 개발을 시작한 **같은 대화**에 아래 프롬프트를 추가합니다. 오류 문구에는 API 키·비밀번호가 포함되지 않게 확인합니다.

```text
방금 만든 앱을 내 컴퓨터에서 실제로 실행하고 핵심 사용자 흐름을 확인해줘.
README와 package.json의 실행 명령이 일치하는지 확인하고 필요한 초기화와 seed를 실행해줘.
기존에 입력한 DB와 업로드 파일을 삭제하지 마.
실행 오류가 있으면 로그를 읽고 원인을 고쳐줘. 타입 검사, 린트, 빌드도 확인해줘.
브라우저 도구가 있으면 핵심 화면과 저장/조회 흐름을 직접 확인해줘.
브라우저 도구나 실제 AI 키/영상이 없어서 확인할 수 없는 부분은 완료했다고 말하지 말고,
내가 확인할 단계와 기대 결과를 적어줘.

```

## 강사가 같이 확인할 완료 기준

- 모든 앱: 화면만 그려진 상태가 아니라 입력·처리·결과가 연결되고 빈 상태와 오류가 표시됩니다.
- DB 앱: 저장 후 새로고침과 서버 재시작에도 데이터가 남고 seed 재실행으로 사용자 데이터가 바뀌지 않습니다.
- 영상 앱: 파일이 업로드 폴더에 남고 브라우저에서 재생·탐색되며 비공개 영상의 파일 API도 보호됩니다.
- AI 앱: 데모 여부가 명확하고 실제 AI 실패 시 기존 입력과 편집 내용이 유지됩니다.
- 사료 앱: 열량 단위별 결과가 일치하고 필요 열량이나 감량 처방을 임의로 만들어내지 않습니다.

첫 프롬프트의 기능을 확인한 뒤 원 기획의 다음 단계로 확장합니다. 팀 공유·외부 공개·배포를 추가할 때는 다중 사용자 인증과 권한, 운영 DB와 파일 저장소를 별도로 설계합니다.
